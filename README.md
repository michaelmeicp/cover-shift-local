# Cover Shift 臨時補班

**0.1.0 · 繁體中文 · 本機多人流程示範**

缺一個人時，由主管說清楚工作，員工主動表示願意，再由主管確認一位。這不是供真實團隊使用的排班系統：角色、人員、場地及班次均為示範資料，請勿輸入真實員工資料。

## 開始

使用 **Node.js 22.13 或更新版本**，不需要 npm 套件、帳戶、金鑰或外部服務。

```sh
npm start
```

開啟 http://127.0.0.1:3030 。預設使用目前目錄的 `cover-shift.sqlite`，重啟會保留資料。如需每次啟動均從合成範例開始，可在 macOS / Linux 執行 `COVER_SHIFT_DB=:memory: npm start`；用 `PORT=3031` 可更換連接埠。Node 某些版本可能顯示內建 SQLite 的 experimental warning，不影響示範。一般瀏覽器視窗共用角色：要同時扮演兩人，請分別使用普通及私密視窗（或不同瀏覽器設定檔），並在操作後重新整理另一個視窗。

剛開始可直接用主管林澄查看「東廊工作間」：何小嵐與已確認的「南岸展室」重疊，梁雨禾則時段相容且所需技能齊備。周木生是尚未表態的示範員工。

## 五分鐘走一輪

1. **主管張貼。** 進入主管示範身分，建立一班「示範展廳／入口指引」。預設以澳門時間填寫，例如 8 月 1 日 23:00 到 **8 月 2 日** 01:30，應顯示 2 小時 30 分。每一班只有一個名額。
2. **員工表態。** 在另一個視窗進入員工身分，找出該班並表示願意。仍在待選時可以撤回、再表態。其他員工看不到這位員工的候選資料；主管則能檢視此班的候選人。
3. **主管決定。** 回主管視窗重新整理，對照所需技能與候選人的一般技能，選擇符合條件的人後確認。系統不會以人員評分排名。確認後不能再選第二位；員工可以在自己的視窗查看結果及站內通知。
4. **試時間衝突。** 建立一班 01:00–02:00、一班 01:30–02:30，選用同一時間區及下一天日期。讓已確認前班的員工分別表態。第一班會與原班重疊，主管不能確認；第二班與原班首尾相接，不算重疊。
5. **取消及追溯。** 主管在原班填寫原因後取消。取消保留歷史，而不再佔用員工時段；此時可確認步驟 4 的第一班（前提是未確認與它重疊的第二班）。若仍有補班需求，請另開新班。於站內通知及稽核紀錄查看變動，沒有任何電郵或簡訊寄出。

## 怎樣計算與保護資料

- 開始、結束皆按班次所列時區解讀，不按裝置所在地猜測。跨午夜請明確選擇翌日。工時取實際時間差；重疊使用半開區間，即前班結束時間等於下班開始時間不算衝突。
- 管理與候選操作由伺服器讀取工作階段後判定，不接受前端自稱的權限。每位員工只可代自己表態或撤回；主管不能代員工報名。
- 每次確認由 SQLite 交易處理，重新檢查候選狀態、班次與時間衝突，避免快速連點造成雙重安排。
- 主管修改內容後，原本待選的意願會撤下，通知員工重新表態；不會默認員工願意接受新安排。技能差異只供雙方留意，不會自動拒絕候選人。
- 站內通知不是對外傳訊。沒有薪資計算、僱用建議、自動排班、分析追蹤、第三方字體或外部素材。請勿填寫住址、健康、薪酬、聯絡或其他可辨識資料。
- 示範身分選擇器對本機使用者開放，**不是正式身分驗證**。切換角色是為了測試；不要在網際網路、共用主機或真實營運環境開放此服務。

## 原始碼與驗證

| 路徑 | 職責 |
| --- | --- |
| `server.mjs` | 內建 HTTP、SQLite、工作階段、權限、交易與本機靜態資源 |
| `public/` | 手機優先介面、原創圖示、系統字體、站內操作 |
| `test/api.test.mjs` | 以隔離資料庫及真正 HTTP 要求驗證多人流程 |
| `.github/workflows/test.yml` | GitHub Actions 在 Node 22.13 與 24 執行語法檢查及測試 |

```sh
npm test       # 不使用或清除一般示範資料庫
npm run check  # 語法檢查及相同測試
```

可重複執行，測試透過記憶體或專用臨時 SQLite 檔隔離；沒有公開重設資料的 HTTP 操作。測試涵蓋 API 角色與隱私、重複候選、撤回、並行確認、跨區及跨日衝突、相鄰時段、取消釋位、站內通知、稽核與重啟保留資料。以上是本機驗證方式，並非遠端 CI 或產品部署證明。
